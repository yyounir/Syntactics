Syntactics — LeetCode Mode

Technical blueprint: Next.js + TypeScript, Gemini for the AI reasoning, a small set of hand-built components for the visualization, Neon + Prisma for saved conversations.

How This Works, In Plain Language

It's one Next.js project — no separate frontend and backend service to wire together. The same project serves the pages you see and runs the server-side code that talks to Gemini and the database.

When you submit a problem, the page calls a backend route inside that same project. That route asks Gemini for a specific shape of answer — not freeform text, but structured data: the UMPIRE breakdown, the complexity reasoning, the concepts involved, and a list of steps describing how the data structure changes. Gemini doesn't draw a picture — it fills in that list. Your own React components draw the boxes for whichever step is active, and Previous/Next buttons step through them. That's how the visualization works for any problem, without image generation.

Saving a conversation writes it to Neon (a hosted Postgres database) through Prisma — a tool that lets the app read and write that database using TypeScript instead of raw SQL.

The Unique Kernel, Built

Gemini returns a steps array — each step says things like "array is [4,2,7], comparing indices 0 and 1." A small, fixed set of React components (ArrayView, LinkedListView, TreeView, RecursionView) render whichever step is active, picked by a type field Gemini fills in. Previous/Next just moves between steps. This is why it generalizes to any problem without image generation.

Data Model

model Conversation {
  id          String   @id @default(cuid())
  mode        String   // "full" | "guided"
  problem     String   // problem number or pasted text
  language    String
  stage       String?  // current UMPIRE stage, guided only
  messages    Json?    // full chat history, guided only
  response    Json?    // UMPIRE/complexity/concepts/steps, full mode
  steps       Json?    // visualization steps, either mode
  createdAt   DateTime @default(now())
  updatedAt   DateTime @updatedAt
}
Where it livesNeon Postgres, via Prisma, from API routes only — never queried directly from the browser.
How it's updatedNew row on first Save; resuming a guided chat and saving again updates messages, stage, updatedAt on that row.
Leave & returnUnsaved conversations are lost on refresh (in-memory only). Saved ones persist indefinitely and reload fully, including resuming guided chats.

Important Failure Modes

  • Non-coding input→Gemini classifies first (or the route catches a malformed reply) and shows an error asking for a valid coding problem.
  • Unrecognized problem number→Gemini still responds with the concepts it can infer, rather than failing outright.
  • Gemini reply doesn't match the expected JSON shape→the route catches the parse failure; UI shows "couldn't generate a response, try again" instead of crashing.

What Was Simplified and Why

  • Stepped JSON + fixed React components instead of AI-generated images or freeform diagrams — Gemini is reliable at filling a known data shape, not at drawing visuals. A handful of hand-built renderers cover the generality the kernel needs.
  • One Next.js project instead of a separate frontend + backend service — removes a layer of wiring (CORS, two deploys) while still giving real backend code to write (the API routes).
  • A single stage field inferred by Gemini per turn instead of a custom state machine — keeps "AI judges progress" without hand-built stage-detection logic.

Decisions and Open Issues

The visualization uncertainty — resolved
The learner wasn't sure how an AI could generate a visualization for any data structure without image generation. Resolved by splitting "what to show" (Gemini fills a structured steps list) from "how to draw it" (a small fixed set of hand-built components) — the learner's own instinct (boxes/tables over images) was right; this spec gives it a concrete data shape to build against.
Database auth clarification
Neon's connection string is a server-to-database credential, not user-facing login. The app itself has no accounts or sign-in.
Saved conversations are resumable
Learner's choice — guided saves include full message history + current stage, so reopening one lets the user keep chatting with full context restored to Gemini.
Save stays a per-conversation button
Learner considered a global settings toggle, decided the existing opt-in Save action already covers it (prd.md > Saved conversations).
Open questions carried from the PRD
None remain — the storage-mechanism question (prd.md > Open Questions) is resolved by Neon + Prisma above.
