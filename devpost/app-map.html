Syntactics — App Map

A snapshot of how the app is built, for finding your way back in later.

What this app does

Syntactics is an AI interview-prep tool. Its one built mode, LeetCode Mode, takes a LeetCode problem (a number or pasted statement), a language, and a response style:

  • Full framework — one page with a UMPIRE breakdown (Understand, Match, Plan, Implement, Review, Evaluate), time/space complexity reasoning, the concepts involved, a working code solution, and a step-through visualization of the data structure in motion.
  • Guided — a back-and-forth chat where the AI questions you through each UMPIRE stage instead of handing over the answer, asking before it advances to the next stage.

Either way, you can save the conversation; it appears in the sidebar, can be renamed or deleted, and reopening it resumes right where you left off (guided chats keep their full history).

A real route through the code: clicking Save

Toured interactively during the build's learning wrap-up.

1
components/SaveButton.tsx — function handleSave
The click handler. It fetch()es /api/conversations (or /api/conversations/<id> with PATCH if a conversation was already saved once). The browser never touches the database directly — it asks the server to.
2
app/api/conversations/route.ts — function POST
Runs only on the server. Reads the request body and calls prisma.conversation.create({ data: {...} }). This is the actual backend logic — the one place that decides what gets written and how.
3
lib/prisma.ts + prisma/schema.prisma
lib/prisma.ts is the one shared database connection every route reuses. schema.prisma is the contract — the Conversation model — that Prisma turned into a real SQL table via npx prisma migrate dev (see prisma/migrations/20261022151110_init/migration.sql). The result: a new row in Neon Postgres, and the conversation now shows up in the sidebar after a refresh.

To change this, start here

  • Change what Gemini is asked for (the UMPIRE prompt, the visualization instructions, the coding-problem classifier) → lib/gemini.ts and lib/visualization.ts.
  • Change the saved-conversation shape (add a field) → edit prisma/schema.prisma, then run npx prisma migrate dev --name <change> (and restart the dev server afterward — a running server keeps its old Prisma Client in memory even after the schema changes on disk).
  • Change the sidebar or saved-conversation UI → components/Sidebar.tsx (list, rename, delete) and components/SaveButton.tsx (the button itself — this is where the label was changed from "Save conversation" to "Save Chat" as a safe practice edit during this build).
  • Change the visualization rendering (how a step is drawn) → components/visualization/ (one file per data-structure type: ArrayView, LinkedListView, TreeView, RecursionView).

A practice to reuse

Every backend feature in this app follows the same shape: the browser can never be trusted with direct database access, so there's always a server-side API route in between that decides what's allowed and forwards the request (see app/api/conversations/route.ts, app/api/leetcode/route.ts, app/api/leetcode/chat/route.ts). When starting a new feature on any future project, the first question worth asking is: what's the client allowed to send, and where's the one server-side place that validates it before it reaches storage? That boundary is what makes a feature "backend" rather than just UI.

Running it again

  1. npm install
  2. Create .env.local with GEMINI_API_KEY (from Google AI Studio) and DATABASE_URL / DATABASE_URL_UNPOOLED (from a Neon project) — see .env.example for the required names.
  3. npx prisma generate (and npx prisma migrate dev if the database doesn't have the Conversation table yet).
  4. npm run dev, then open http://localhost:3000 (or whatever port it prints).
